# 言绘 LiveCanvas v17（旧版归档说明）

本地优先的实时演讲可视化原型。双击 `start-demo.cmd` 后访问 `http://127.0.0.1:4175`。

## 本轮能力

- 中文、英文和中英混合文本解析；语音识别可切换浏览器基线或本地 WhisperLiveKit。
- 语音入口已抽象为可切换 ASR Provider；当前浏览器识别只作为基线和降级方案，WhisperLiveKit 走本地 WebSocket `ws://127.0.0.1:8000/asr`，候选文本不再因为包含绘图结构词而获得额外分数。
- 内置“ASR 评测”面板，可录制原始 WebM 音频并输出 CER、WER、首批文字延迟、首个最终句延迟和临时文本修订次数；音频与 JSON 报告可下载留作版本回归。
- ASR 评测会根据标准文本自动切换 `zh-CN` 或 `en-US`；检测到中英混合时会按当前 Provider 提示风险，浏览器基线会标记为不可靠，WhisperLiveKit 可用于本地流式对比。
- 新增流式文本稳定器：第一版临时识别只显示字幕，不直接绘图；只有重复出现的稳定前缀或最终句才进入视觉结构，减少英文临时识别跳动导致的误画。
- 稳定器会把一句话拆成可绘图的小段，保留未稳定尾巴作为字幕；画面状态会显示 `DRAFT`、`STABLE+` 或 `CONFIRMED`，评测报告会记录稳定触发、草稿抑制和前缀修正次数。
- 新增上下文纠错层：原始浏览器 ASR 会继续保存在报告里，但进入画图和最终稿前会先修复低风险英文误听，例如 `library canvas` → `live visual canvas`、`stable tax` → `stable text`、`girl is not to create more slides` → `goal is not to create more slides`。
- ASR 评测面板新增本地术语/误听词库，格式为 `正确术语 = 误听1, 误听2`；词库保存在浏览器本地，并会在下一次录音时参与上下文纠错。
- 评测报告新增纠错对照表、词库触发次数，以及原始识别与理解修正后的 CER/WER 对比，用来判断纠错是否真的提升准确率。
- 每次评测还会自动归档到 `work/asr-evaluation/audio` 与 `work/asr-evaluation/reports`，方便后续版本使用完全相同的真实讲话做比较。
- 双层理解：本地快速解析立即出图，多语言 MiniLM 向量模型在浏览器后台用余弦相似度修正结构类型。
- 新增视觉意图引擎：每句都会先判断更像主题、流程、组成、清单、因果、问题方案、观点证据、数据还是普通字幕，再决定是否提升、改判或抑制结构图；右上角调试提示会显示当前意图分数。
- 英文结构触发更保守：`First reason` 会进入清单而不是流程，单独提到 `problems` 不会立刻画问题方案，`because` 默认优先进入因果判断；`account for 20%` 这类占比会稳定画饼图。
- 流程、包含关系、清单、对比、结论、占比饼图、增长/下降柱状图。
- 跨句逻辑记忆会把主张与证据、问题与方案、原因与结果组合成持续生长的视觉单元；普通提到“问题”不会直接触发问题图。
- 双画面布局：左侧固定上一段已确认结构，右侧逐字更新当前内容；同一逻辑单元原位生长，只有新主题才交接画面。
- 流程和清单使用生命周期状态机：显式步骤继续，主题切换立即关闭，连续两句语义偏离后退出；关闭后的句子会重新参与主题、结论和图表判断。
- 已确认节点冻结；中文节点约 22 字、英文节点约 12 个词，并通过三行上限保持卡片尺寸接近。
- 过滤“呃、额、嗯、那个、就是说、um、uh、you know”等口水词；结构词仍参与判断但不进入图中。
- 导出独立可编辑 HTML，以及包含原生文本框、形状和图表的可编辑 PPTX。
- 本地注册、登录与项目同步 API；未登录时内容只保存在浏览器本机。
- PWA 外壳和 Service Worker，页面资源可离线缓存；本地开发地址会自动清理旧 LiveCanvas 缓存，避免测试到上一版脚本。

## 语义模型

第一次在页面中输入或讲话时，会从 Hugging Face 载入 `Xenova/paraphrase-multilingual-MiniLM-L12-v2` 的量化浏览器模型。模型通过 Transformers.js 在客户端运行，首次下载后由浏览器缓存。加载失败或超过 30 秒时，应用自动继续使用本地快速解析，不阻塞实时绘图。

数字和百分比不交给向量模型猜测，而是由确定性数值解析器处理：

- `移动用户占20%` / `Mobile users account for 20%` → 饼图
- `用户增长20%` / `Users grew by 20%` → 以前 100、现在 120 的柱状图
- 多个百分比项目 → 对比柱状图

## 本地 ASR

WhisperLiveKit 0.2.22 和 `faster-whisper-small` 多语言模型已经安装在项目的 `work` 目录，不依赖系统 Python，也不会在日常启动时再次下载。

1. 双击 `start-whisperlivekit.cmd`，等待窗口显示服务已监听 `127.0.0.1:8000`，使用期间保持该窗口打开。
2. 双击 `start-demo.cmd` 打开 LiveCanvas。
3. 在页面控制栏把语音识别引擎切换为 `WhisperLiveKit（本地）`，语言选择 `Auto / 中英混合`，然后点击“开始聆听”。

本地服务使用 CPU int8、`small` 多语言模型、LocalAgreement 流式策略和 PCM 音频输入，页面默认连接 `ws://127.0.0.1:8000/asr`。浏览器 Web Speech 仍作为无需本地服务的降级方案。WhisperLiveKit 返回的临时文本和最终句会继续复用现有的文本稳定器、上下文纠错、视觉意图引擎和 ASR 评测面板。

## 账户与部署

`server.js` 仅使用 Node.js 内置模块，提供静态页面、注册、登录和最新项目同步。密码使用带随机盐的 `scrypt` 哈希；会话使用 HttpOnly、SameSite Cookie。

本机运行默认只监听 `127.0.0.1`。部署到服务器时设置：

```powershell
$env:HOST="0.0.0.0"
$env:PORT="4175"
$env:NODE_ENV="production"
node server.js
```

公开部署必须放在 HTTPS 反向代理后，并把 `work/local-server-data` 替换为正式数据库和持久化会话存储。当前文件数据库适合 Demo 和单机试用，不适合大规模并发。

## 当前边界

- 浏览器 Web Speech API 对真正的中英混合语音识别不可靠。当前已能切到 WhisperLiveKit，本地服务质量取决于你选择的 Whisper 模型、麦克风和机器性能。
- 纯英文模式应在输入框右侧选择 `English`，这会让当前 ASR Provider 使用英文提示；英文结构解析已覆盖 `start by`、`followed by`、`once that is done`、`the takeaway is`、`moving on to` 等表达。
- 向量模型负责“这句话更像流程、关系还是结论”，具体数字、实体和步骤仍由结构化解析器抽取。这种混合方式比完全依赖关键词更智能，也比每个字都等待大模型更实时。
- 真实长演讲回放与评测位于 `..\evaluation-report`；当前语料包含 10 场中英文 TED 演讲，共 140.8 分钟。
